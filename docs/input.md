# 入力欄・画像の貼り付け

## 複数行の入力

通常の対話入力欄は基本3行です（高さの足りない端末では画面内に収めます）。改行や折り返しに応じて広がります。起動画面では上下へ、会話中は履歴領域を確保しながら上へ広がります。画面の高さを超えた分は入力欄内でスクロールし、カーソル位置を表示します。

| 操作 | キー |
| --- | --- |
| 送信 | Enter |
| 改行 | Ctrl+J。端末が対応していればShift+Enter / Option+Enterも使用可能 |
| 行を移動 | ↑ / ↓ |
| 行頭・行末 | Home / End、Ctrl+A / Ctrl+E |
| 入力を消去 | Ctrl+U |
| Macでテキストを貼り付け | Cmd+V（端末の「ペースト」） |
| Macで画像を添付 | Ctrl+V |
| 最後の添付画像を削除・画像読込を中止 | Ctrl+X |

Cmd+VはmacOSの端末側が処理するショートカットです。MODKHではテキスト貼り付けを横取りしません。bracketed pasteに対応した端末では、貼り付けた改行を保ち、末尾に改行があっても自動送信しません。複数行の `/exit` などは会話本文として扱い、コマンドを実行しません。

操作の承認を求められたら、↑↓で「拒否」か「承認」を選び、Enterで確定します。初期選択は「拒否」です。表示から3分経つと自動で拒否します。行入力モードでは `y` と Enter で承認します。

## マウスで会話をコピーする

会話中の行をドラッグすると、離した時点で選択範囲をクリップボードへコピーします。折り返しで分かれた行はつなげ、サイドバーや行頭の余白は含めません。

画面の上端・下端までドラッグしたままにすると、その間は履歴を送り続けます。表示が切り替わっても選択範囲は保たれるので、1回のドラッグで複数ページにまたがる出力をまとめてコピーできます。ドラッグ中はホイールやPgUp/PgDnでも送れます。選択の端点は行と文字位置で保持するため、スクロールや端末幅の変更でずれません。

ドラッグを始めた行が履歴の対象外にある場合(起動前の案内など)は選択を開始しません。コピーできたかは入力欄の下に「選択範囲をコピーしました」と表示します。

プロバイダー検索と認証キーは1行で入力します。`MODKH_PLAIN=1` や非TTYの行入力モードでは、複数行エディター・クリップボード画像は使わず、従来の1行ずつの入力を維持します。

## `@` でローカルファイルを添付する

会話入力欄の先頭か空白の直後で `@` を入力すると、作業ルートのファイル・フォルダー候補が表示されます。`@src/` のようにパスを入力して絞り込み、**↑↓** で選び、**Tab** で補完します。フォルダーを補完すると、その中の候補が表示されます。**Esc** で候補を閉じられます。

```text
@src/main.ts と @"docs/画面 仕様.md" を比較して
```

直接入力もできます。空白を含むパスは二重引用符で囲んでください。候補表示とTab補完は対話端末のみですが、行入力モードでも入力したパスは使えます。`\@` と書けばファイル参照として扱われません。

Enterで送信したときにファイルの内容を読み込み、依頼文と一緒にモデルへ渡します。作業ルート内のファイルを8件まで指定できます。例: `@notes.md @画面.png @写真.jpg @仕様.pdf を比較して`。`@` で指定したPNG・JPEG・PDF・UTF-8テキストは、1回の送信で合計256 MiBまで添付できます。PNG・JPEGは元ファイルの形式・解像度・画質のまま、最初のリクエストに添付します（1枚4,000万画素まで）。テキストは合計8 KiBの直接添付枠を超えるファイルをOSの一時ディレクトリにコピーします。モデルは参照IDを使い、必要に応じて `inspect_attachment` で4 KiBずつ読みます。一時コピーはチャット終了時に削除されるため、再開後は再添付してください。PDFはこの方式の対象外です。接続先のモデルには別途、送信サイズやコンテキストの上限があります。画像やPDFは対応するモデルが必要です。大きなPDFやページ指定には `/pdf --pages 2-4 @仕様.pdf 要約して` を使ってください。ファイルを読み込めなければ送信を止め、対話端末では入力欄に依頼を戻します。

添付内容はセッション履歴にも保存されます。機密情報を含むファイルを指定するときは、モデルの送信先と履歴の保存に注意してください。

## Macで画像を送る

1. スクリーンショットや画像そのものをクリップボードへコピーします。
2. MODKHの会話入力欄で **Ctrl+V** を押します。
3. 「画像を読込中…」の後に **画像1枚** などの添付表示を確認します。
4. 必要なら説明を入力し、Enterで送信します。画像だけでも送信できます。

画像がない、読み取れない、大きすぎる場合は入力欄に理由を表示します。既存のテキストと他の添付画像は消しません。Ctrl+Xで最後の画像を削除できます。読込中の送信は行わず、完了後のEnterを待ちます。Ctrl+Cによる入力取消や終了時は、読込を中止し、遅れて届いた画像を追加しません。

画像貼り付けは現在macOSのみ対応しています。macOS標準のAppKitと `osascript` を使い、PNGまたはTIFFの画像データを読み取ります。TIFFはPNGに変換します。ファイルパスやURL、クリップボードのテキストを画像として読み込むことはありません。端末やOSの権限制限で失敗する場合もエラーとして表示します。

上限は **4枚、1枚5 MiB、4,000万画素**です。テキストは128 KiBまでです。上限超過を黙って切り捨てたり、画像を外してテキストだけ送信し直したりしません。

## モデル・保存先について

- **画像に対応したモデル**へ接続してください。MODKHはAI SDK / OpenAI互換APIおよびChatGPT Responses APIへ画像コンテンツとして渡します。個々の接続先が画像に対応するかはモデル次第です。
- 非対応モデルやAPIで拒否された場合は、そのエラーを表示します。別モデルへの自動切替や、画像を除いた自動再送はしません。`fixed/scripted` は動作確認用で、画像を理解するモデルではありません。
- 未接続時の画像や、`/connect` などの操作中の添付は保持します。画像は次の通常の会話送信で親モデルへ渡し、サブエージェントへ自動コピーしません。
- **送信した画像データもテキストと同じセッション履歴へ保存されます。** 再開時に読み戻せます。失敗した送信も履歴に残ります。機密画像を添付する場合は送信先と履歴の保存に注意してください。
- 画像の内容やbase64を端末のログに展開せず、添付枚数だけを表示します。画像を自動でメモリサービスへ渡すことはありません。

実端末でのCmd+VとCtrl+Vの挙動は、使用するターミナルのキー設定・クリップボードアクセス権にも依存します。

## トークン使用量の表示

モデルが使用量を返した場合、入力欄の下に1行で表示します。返さない場合は何も表示しません（推測値は出しません）。

```text
計 4.9M tok · cache 100% · 入 4.5M · 出 410k
```

- `計`: 入力＋出力の合計。`入`: 入力トークン（プロバイダーがキャッシュ分を含めて数える場合はその値）。`出`: 出力トークン。
- `cache`: 入力のうちキャッシュから読んだ割合。入力が0のときは表示しません。キャッシュ読取りが入力に含まれない集計をする接続先では値の意味が変わります。
- 端末幅が足りないときは右側の項目から落として1行を保ちます。折り返して入力欄を押し下げません。
- 行入力モード（`MODKH_PLAIN=1`・非TTY）では、各応答の後に `(使用量: …)` として1行出します。
- 表示はセッション内の累計です。再起動すると0から数え直し、履歴の分は含みません。保存もしません。

## 処理中の状態と長い検索結果

- 対話画面では現在の状態と、その状態に入ってからの経過秒数を表示します。ChatGPT 接続ではサーバーが要求を受理すると表示が切り替わります。推論やツール要求の開始が届くとその状態に切り替わり、ツール名が分かれば実行前から表示します。Ctrl+Cで中止できます。
- 対話画面では回答が終わると、お祝いのAAが1枚出ます。10種類が一巡するたびに順番が変わります。中断やエラーのときは、その理由を表示します。
- `search_files` はGit管理下ではGitの除外設定を適用します。Git管理外では `.git`、`node_modules`、`.agenticreplay`、`dist` などの生成・管理ディレクトリを除外します。最大50件・出力16 KiBで、長い行は一致箇所の周辺だけを省略表示します。探索上限や読めなかったファイルも明示します。
- 長いツール結果はモデル入力に限って1件16 KiB、ツールメッセージ1件の本文を合計128 KiBに制限します（省略注記やメッセージ構造は別）。省略は明示し、呼び出しIDと成功・失敗・結果不明の状態は保ちます。セッションの原記録は削除・上書きしません。
- 長い会話は、直近のターンを残してモデル入力だけを[自動圧縮](context-efficiency.md#会話履歴の自動圧縮)します。圧縮中は Ctrl+C で中止できます。
- この版以降はエラーの説明も状態イベントに最大2,048文字で残し、再開時に表示します。過去の版で保存されなかったAPIエラーの詳細は復元できません。

再開する場合は元の作業ディレクトリで `node dist/index.js chat --resume <セッションID>` を実行し、必要なら `/connect` で再接続します。ビルド更新は、すでに起動中のプロセスや別途インストールしたグローバル版へは自動反映されません。

## ツール表示と詳細

TUIでは操作名・対象・結果を短く表示します。作成するファイルの本文、長いJSON、読み込んだ手順の全文は通常表示に流しません。
コマンドの終了コード、失敗・未実行・結果不明、診断の要約は残します。
`/tools` で直近20件のツール履歴を表示し、`/tools <番号>` でその呼び出しの引数と結果を全文表示できます。
これは表示だけの整理です。モデルに渡す結果やセッション原記録はこの表示処理で省略しません。行入力モードは従来の出力を保ちます。

## browseによるブラウザ検証

PATH上に実行可能な `browse` がある場合、`browse` ツールを登録し、コマンドツールの説明にもブラウザ操作の経路を追加します。
コマンド権限のある親・子エージェントに共通して適用し、権限のない担当にはコマンド権限を追加しません。
`browse --help` と `browse status --json` で使い方・接続状態を確認します。
プロジェクト内のPlaywrightパッケージがないことと、browse経由でブラウザ操作できないことを区別します。
実行ファイルの検出だけでは拡張機能の接続を保証せず、インストールやペアリングも自動では行いません。

### 提供する操作

| 操作 | 引数 | 内容 |
| --- | --- | --- |
| `status` | なし | リレー・拡張の接続状態と、使えるタブを返す |
| `navigate` | `url`、任意の `tab` | `tab` を渡すとそのタブを移動し、省略すると新しいタブを開く |
| `snapshot` | `tab` | 操作対象を選ぶための要素一覧と `ref` |
| `click` | `tab`、`ref` | 要素をクリックする |
| `fill` | `tab`、`ref`、`text` | 入力欄を `text` で置き換える |
| `screenshot` | `tab`、任意の `ref`・`full` | 画面・要素・ページ全体を撮る |
| `list` | なし | このターンで開いたタブのIDとURL |

`navigate` 以外は `tab` が必須です。`ref` は直前の `snapshot` が返したものです。
`browse execute` などの任意スクリプトは `browse` ツールに含めません。スクリプト実行は `run_command` の承認設定に従います。

### スクリーンショット

撮影したPNGは `.modkh/browse/<tab>.png` に保存し、画像としてモデルへ渡します。同じタブの再撮影は上書きするため、ファイルは増えません。
撮影に失敗したときは前回の画像を渡さず、CLIのメッセージを返します。5 MiB・4,000万画素を超える画像は保存だけ行い、添付しなかった理由を返します。

### タブの後片付け

`browse` ツールで開いたタブとポップアップは、応答の完了・エラー・中断時に自動で閉じます。終了を確認できなかった場合はグループ名を表示し、セッション終了時にも再確認します。ユーザーが開いているタブは閉じません。

### 使用中の表示

`browse` ツールの呼び出しが実行中の間、トークン使用量と言語サーバーの並びに `browse in use` を出します。
親・子・`/agents run` のどの経路でも同じ表示になります。呼び出しが終わると消えます。

- 表示は実行中かどうかだけで、接続状態や操作の成否は表しません。接続確認は `browse status --json` で行います。
- 端末が右欄を置けない幅・高さでは、入力欄下の状態行の末尾に `· browse in use` を付けます。
- 行入力モード（`MODKH_PLAIN=1`・非TTY）では、開始と終了を1回ずつ `(browse in use)` と `(browse 終了)` で出します。
- 表示はツールの権限・承認・記録を変えません。モデルに渡す結果も同じです。

## PDFを見ながら実装する

画像対応モデルに接続して、会話入力欄で次のように依頼します。行入力モードでも使えます。

```text
/pdf @docs/画面仕様.pdf
/pdf --pages 5-7 @"docs/画面 仕様.pdf" | この3ページにある入力項目と検証条件を反映して
```

対話端末で `/pdf @` と入力すると、作業ルート内のPDFとフォルダーが候補に出ます。**↑↓** で選び、**Tab** で補完します。パスを直接入力するときは、空白を含む名前でも `/pdf docs/画面 仕様.pdf` と書けます。ファイル名に `|` を含むときは `@"パス"` と指定してください。`/pdf @画面仕様.pdf 変更点を教えて` のように、パスの後に空白を入れて依頼文を書き、Enterで送信できます。従来の `| 依頼文` も使えます。依頼文を省略するとPDFの要約を依頼します。読み込みに失敗した場合、対話端末ではコマンドが入力欄に戻るので、パスやページ範囲を直して再送できます。

通常のチャットでも `~/Downloads/newkoku.pdf 読める？` のようにパスを渡すと、確認なしでそのファイルを添付します。空白を含むパスは二重引用符で囲んでください。見つからない場合は、同じフォルダ内の候補名を表示します。候補の中身は読みません。`/pdf ~/Downloads/mobatike.pdf` も確認不要です。ただし、作業ルート内のパスがシンボリックリンクで外を指す場合、`/pdf` は確認します。

ページ番号は1から始まり、単独ページは `--pages 5` と指定します。範囲を省くと全ページが対象です。

PDFはローカルで変換します。macOSでは `brew install poppler`、Ubuntuでは `sudo apt install poppler-utils` で必要なコマンドを導入できます。選んだ各ページのテキストと、図・写真・配置を含むページ全体のPNGを親モデルに送り、会話履歴にも保存します。スキャンした資料はページ画像をモデルが読み取ります。

PDFは512 MiBまで読み込めます。依頼文はパスの次の行からでも入力できます。1回に送れるページ数は貼り付け済みの画像と合わせて8枚までで、超過時はページ範囲を指定し直せます。各ページの画像は長辺1600ピクセル、本文は1ページ32 KiBまでです。
