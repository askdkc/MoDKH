# /cyber

MoDKH の入力欄で `/cyber <URL>` を実行すると、その URL を対象に次の順で点検する。承認画面にはクエリを伏せた URL、接続するポート、実行する検査、起動しない検査を表示する。接続先は指定したホストだけで、リダイレクトは追跡しない。

| 検査 | 確認する内容 |
| --- | --- |
| DNS | A/AAAA、SPF、DMARC、CAA。SPF と DMARC がない場合は指摘する |
| Nmap | URL のポート1つと、代表的な16ポートの公開状態。データストアのポートが公開されていれば指摘する |
| TLS（HTTPS） | 証明書チェーン、有効期限、SAN、TLS バージョン（openssl） |
| HTTP | セキュリティヘッダー、Cookie の属性、CORS、OPTIONS の Allow、公開されない前提の固定パス4件、混在コンテンツ、例外の露出 |
| nuclei | 導入とテンプレートがある場合だけ中〜重大のテンプレート検査。未導入なら「未実行」 |

`/cyber <URL> --source .` は、上記に加えてそのディレクトリを点検する。`.` はそのサイトに対応すると利用者が指定したチェックアウト。パスはワークスペース内の実在するディレクトリに限り、シンボリックリンクの外は拒否する。空白を含むパスも指定できる。

| ツール | 確認する内容 |
| --- | --- |
| Trivy | 依存パッケージの既知の脆弱性（JSON を解析） |
| OSV-Scanner | ロックファイルなどのパッケージと OSV の勧告（JSON を解析） |
| Semgrep | p/default のルールに該当するファイルと行 |
| Gitleaks | 秘密情報の候補。`--redact=100` で値を伏せ、位置とルール名だけを表示する |

Trivy と OSV-Scanner が同じ勧告を指摘したときは出典を併記し、1件として数える。`--sqlmap-summary <JSON>` を付けると、`{"target": "...", "date": "...", "verdict": "..."}` の形の外部診断の要約を、対象 URL が一致するときだけ表示する。MoDKH は sqlmap を起動しない。

引数なしの `/cyber` は従来どおり作業ディレクトリの4ツールを実行し、`/cyber tools [URL]` はツールの版を表示する。`/cyber gitleaks` のように小文字の実行ファイル名を指定すると、そのツールだけを実行する。

各検査は「検出あり」「検出なし」「未実行」「失敗」「中断」を分けて表示する。ツール未導入は「未実行」であり「検出なし」ではない。Ctrl-C は実行中のプロセスにも伝え、残りの検査を開始しない。

結果をまとめるときは、検出内容と対象ファイル、実行エラー、対象ファイルがなかった項目を分ける。URL 側の検査は稼働中の応答だけを見るため、ソース側の指摘が本番にもあるかはデプロイしたリビジョンとの照合で決まる。HTML から読み込む CDN ライブラリは依存関係のスキャンで網羅できない。
